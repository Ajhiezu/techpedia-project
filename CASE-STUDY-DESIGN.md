# Portfolio Detail / Case Study — High-Fidelity Template

## Template Status

This is a reusable high-fidelity template, not a fictional case study. It is activated only when a project, client disclosure, visuals, scope, and outcomes are permitted for publication. If case-study depth is insufficient, use one Project Detail page rather than creating a separate `/case-study` route.

## Desktop Composition

```text
HEADER + BREADCRUMB
OVERVIEW HERO: project context 7/12 | approved visual 5/12
PROJECT OBJECTIVE: concise narrative
CHALLENGES: 3 cards
SOLUTION: narrative + system/experience visual
FEATURES / DELIVERABLES: structured list
TECHNOLOGY / CONSIDERATIONS: validated facts only
SCREENSHOTS: approved gallery
RESULTS / IMPACT: validated facts only, otherwise omitted
RELATED PROJECTS: valid items only
FINAL CTA
FOOTER
```

## Section Specification

| Section | Layout & component | Publication requirement |
| --- | --- | --- |
| Overview | Breadcrumb; category label; H1 project name; short permitted context; metadata rail; 5-col visual. | Client name may be anonymised; role/scope must be accurate. |
| Objective | Narrow readable column with project objective. | Approved project context. |
| Challenges | Three issue cards on Light Background. | Actual challenge statements, not generic filler. |
| Solution | 6/6 split narrative + approved interface/system visual. | Accurately distinguish Techpedia Project’s contribution. |
| Features | White modular list/tags. | Only delivered/approved features. |
| Technology stack | Bordered information row or logo-free tags. | Named stack only after confirmation and permission; otherwise omit. |
| Screenshots | 16:10 or device-frame gallery with captions. | Approved screenshots, with sensitive data removed. |
| Results | Deeply restrained result block, not a statistic banner. | Only measured/validated outcomes; omit entire section otherwise. |
| Related projects | Up to three project cards. | Valid projects only; omit if unavailable. |
| CTA | Deep Blue band, `Discuss Your Project` and `Back to Portfolio`. | General conversion route. |

## Evidence Matrix

| Data type | Can appear? | Rule |
| --- | --- | --- |
| Project name/category | Yes, if approved. | Accurate and permitted. |
| Client logo/name | Conditional. | Written/publication permission required. |
| Screenshots | Conditional. | Approval and sensitive-data review required. |
| Technology stack | Conditional. | Must reflect actual project and disclosure rules. |
| Results/KPI | Conditional. | Measurable, attributable, approved; no extrapolation. |
| Testimonial | Conditional. | Authentic quote, attribution, permission. |

## Responsive & Accessibility

- Desktop uses overview split; tablet may retain split at comfortable widths; mobile stacks context then visual.
- Screenshot gallery becomes one column/controlled carousel on mobile; alternative text/captions explain meaningful visuals.
- Metadata converts to a short vertical list on mobile; long project names wrap naturally.
- Do not make screenshots the sole source of critical information; all essential narrative is available as text.
