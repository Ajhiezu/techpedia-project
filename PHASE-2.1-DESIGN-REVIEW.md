# Phase 2.1 Design Review — Visual Direction & UI Foundation

## Status

**Submitted for approval.** Phase 2.1 establishes the visual direction and shared UI rules only. It does not authorise homepage production/prototyping, other page designs, or Phase 3 development.

## Scope reviewed

The Phase 1 planning, brand, IA, journey, conversion, wireframe, responsive, token, component, and accessibility artefacts were reviewed as the controlling baseline. The following Phase 2.1 artefacts were checked against it:

- `VISUAL-REFERENCE.md`
- `MOODBOARD.md`
- `VISUAL-DIRECTION.md`
- `UI-STYLE-GUIDELINES.md`

## Decisions confirmed

| Area | Approved direction for subsequent design work |
| --- | --- |
| Brand expression | Corporate Professional with Product Clarity: calm, structured, capable, and collaborative. |
| Palette | White and `#F4F7FC` remain dominant; Royal Blue `#2457D6` is reserved for actions and emphasis; Deep Blue `#163B8C` is used sparingly. No new brand colour is introduced. |
| Type | Plus Jakarta Sans for display/headings and Inter for body/UI, using the Phase 1 token scale. |
| Layout | 12/8/4 column system, 1200 px desktop maximum container, and Phase 1 spacing/breakpoint rules. |
| Visual language | Original interface frames, process diagrams, modular panels, and restrained line icons. These must explain an idea and cannot imply real customers, performance, products, or technology stacks. |
| Surfaces and motion | Light surfaces, precise borders, quiet shadows, and 150–250 ms non-essential motion with reduced-motion alternatives. |
| Trust content | No fabricated statistics, client logos, testimonials, case studies, team claims, contact routes, or operational promises. Conditional sections use the documented approach/fallback treatment. |
| Accessibility | WCAG 2.2 AA baseline: visible focus, keyboard-operable disclosure/navigation, 44 px touch targets, clear state messaging, responsive reflow, and no motion-only meaning. |

## Review findings

| Finding | Resolution / rule for Phase 2.2 |
| --- | --- |
| There is no connected Figma or visual-design document session, and the workspace contains no editable visual artboard. | The homepage high-fidelity design must be created in an isolated design prototype/artboard in Phase 2.2, not in a production application. |
| The existing homepage design brief uses English hero/CTA copy (`Start a Project`, `Explore Our Work`, `Let's Talk`), whereas Phase 1 recommends Indonesian operational CTAs. | Treat the English homepage copy as a review-state exception only; obtain explicit approval before it becomes the final homepage copy. All other pages remain aligned to the Phase 1 CTA library unless separately approved. |
| Featured Projects, testimonials, contact/social destinations, approved logo asset, and named technology proof remain unverified. | Use the Phase 1 fallback: approach/process content, no testimonial section, `TBD` only in private review artboards, and no public-looking proof placeholders. |
| A heading in the homepage brief proposes a six-stage process while the About/process planning has a different operational grouping. | Keep the visual sequence generic and describe it as a design model until the operational process is confirmed; do not publish it as a service guarantee. |

## Design-review result

The visual direction is consistent with Phase 1, preserves the approved identity, and has no blocking accessibility or trust-content violation at the guideline level. The findings above must be retained as constraints in the homepage high-fidelity work.

Approve Phase 2.1 to begin **Phase 2.2 — Homepage High-Fidelity Design**. That sub-phase will create the first viewable/editable, isolated design prototype and its desktop/mobile review materials. No Phase 3 work will start without separate approval.
